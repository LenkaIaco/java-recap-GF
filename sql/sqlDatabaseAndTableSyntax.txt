renaming db in MySQL: earlier RENAME keyword, discontinued in MySQL. Instead, create backup of oldDB via command line interface:
mysqldump -u root -p oldDB > oldDB_backup.sql		-- mysqldump is tool for exporting. Having installed MySQL on your machine, mysqldump is included automatically.
							-- Then, insert username and password:
							--   -u logs user 'root' 
							-- -p for opening password prompt. If written directly in command line, it remains in command history and can leak into logs or scripts:
Afterwards, create new-named database. Only after it has all the data, drop the old database.						mysqldump -u root -pMyPassword oldDB > oldDB_backup.sql

---------------------------------------------------------------------------
JOINS + EXCEPT
---------------------------------------------------------------------------
-- as joins work with 2 tables, they use tableref.columnref syntax (not just column name, but table.column ref! )
- Usually, for readability, the 2 table names get their abbreviations. It is called 'aliases'. For SELF JOIN, aliases are mandatory!
-- JOIN = INNER JOIN
-- OUTER JOINS: LEFT OUTER JOIN (= LEFT JOIN), RIGHT OUTER JOIN (= RIGHT JOIN), FULL OUTER JOIN (=FULL JOIN - NOT supported in MySQL)

SELECT c.name, o.order_id, o.amount FROM customers c 
JOIN orders o 
ON c.id = o.customer_id;

INNER JOIN returns only the records that have matching values in both tables.
LEFT JOIN returns all records from the left table and matching ones from the right table.
RIGHT JOIN returns all records from the right table and matching ones from the left table.
FULL JOIN returns all records when there is a match in either table.
SELF JOIN is basing a join on column sets from the same table: colA+colD vs joining colD+ColG based on colD:
	      E.g. table secret_santa:	 Color1   Name  Color2
					 Blue     Jane  Orange
					 Orange   John  Green
					 Red      Paul  Blue
					 Green    Mary  Red

		We want to get a table of name - name pairs who is whose secret santa:
		SELECT a.Name, b.name AS Santa
		FROM secret_santa AS a
		JOIN secret_santa AS b
		ON a.Color1 = b.Color2;
		
		Result:  Name  Santa
			 Jane  Paul
			 John  Jane
			 Paul  Mary
			 Mary  John

SELECT * FROM CUSTOMERS 
ORDER BY AGE ASC, SALARY DESC
LIMIT 5
OFFSET 5				-- combination of JOIN + OFFSET targets specific lines of table from the top
;


SELECT * FROM CUSTOMERS
ORDER BY ( CASE ADDRESS
   WHEN 'DELHI' 	 THEN 1		-- 1 is the sort priority
   WHEN 'BHOPAL' 	 THEN 2
   WHEN 'KOTA' 	 THEN 3
   WHEN 'AHMEDABAD' THEN 4
   WHEN 'Hyderabad' 	THEN 5
   ELSE 100 END) ASC, ADDRESS DESC;	-- anything else has sort priority 100

----------------
GROUP BY
----------------

Group BY is used by SQL rules if: 
	- if there is an aggregate function(SUM, COUNT, MAX, MIN, AVG ) among the columns in the SELECT clause
	- otherwise if every column from SELECT clause is mentioned in the GROUP BY statements

using SELECT + aggregate function:
- If used with other non-aggregate columns, it MUST be accompanied by GROUP BY the other (non-aggregate) column:

	SELECT Buildings.Building_name, COUNT(Employees.Name)  		-- aggregate functions should be followed by () without whitespaces in between
	FROM Buildings LEFT JOIN Employees
	ON Buildings.Building_name = Employees.Building
	GROUP BY Buildings.Building_name;

SELECT h.ID, h.NAME, h.SALARY FROM high_earners h 
GROUP BY h.ID, h.NAME, h.SALARY;

SELECT c.name, SUM(o.amount) AS total_amt 	-- result table will have new column: total_amt
FROM customers c
JOIN oders o 
ON c.name = o.name
GROUP BY c.name			-- order: all JOIN statements, even multi-level, must come before GROUP, HAVING and WHERE statements
HAVING total_amt >400	-- HAVING is used for AGGREGATE columns(SUM,COUNT,MAX,MIN,AVG), as opposite to WHERE in JOINs or WHERE on columns. Here, it filters target's 'calculation' column
ORDER BY c.name ASC;


SELECT game.id, game.mdate, COUNT(goal.matchid) AS goals_scored
FROM game JOIN goal
ON game.id = goal.matchid
WHERE game.team1 LIKE 'POL' OR game.team2 LIKE 'POL' 		-- WHERE comes BEFORE the GROUP BY clause
GROUP BY game.id, game.mdate;					-- SQL requires to list all non-aggregate columns in GROUP BY if an aggregate column(COUNT here) is used previously
SELECT AGE, COUNT(Name) FROM CUSTOMERS GROUP BY AGE;  -- returns age + count (could be represented by other columns than name too)

SELECT ADDRESS, AGE, MIN(SALARY) AS MIN_SUM 
FROM CUSTOMERS 
GROUP BY ADDRESS, AGE HAVING AGE>24;		-- having: adds possibility of condition(filter)
